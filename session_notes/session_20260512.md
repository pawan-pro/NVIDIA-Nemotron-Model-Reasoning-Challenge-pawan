## K-12 explanation captured
The session also clarified the training workflow in simple terms.

### Notebook A
Notebook A is the teacher that reads `train.csv`, classifies problems, and writes worked examples.

It does two jobs:
1. Classifies the problem type:
   - `bit_manipulation`
   - `gravity`
   - `unit_conversion`
   - `numeral`
   - possible skipped categories like `cipher` / `equation_symbolic`
2. Generates hard-coded solution traces using Python rules/templates, not by calling Nemotron or another LLM.

Output:

```text
train_traces_v2_bit.jsonl
```

Each record is chat-shaped:

```json
{
  "role": "user",
  "content": "Puzzle prompt..."
}
{
  "role": "assistant",
  "content": "Hard-coded worked solution... \\boxed{answer}"
}
```

### Notebook B
Notebook B is the teacher/training session.

It:
1. Loads base Nemotron.
2. Attaches a rank-32 LoRA adapter.
3. Reads the trace JSON from Notebook A.
4. Shows user/assistant examples to Nemotron.
5. Optimizes LoRA weights to reduce token prediction loss on the assistant solution text.

Current assistant-only experiment:

```text
adapter_sft_v2_bit_bal128_asstloss
```

Selected 128 examples:

```python
SAMPLE_PLAN = {
    "bit_manipulation": 65,
    "gravity": 21,
    "unit_conversion": 21,
    "numeral": 21,
}
```

Assistant-only loss means:
- do not grade/copy the user prompt;
- optimize only the assistant worked solution / answer side.

### Notebook C
Notebook C is the packaging office.

It:
1. Finds the exact adapter zip by tag.
2. Extracts the adapter.
3. Confirms required files exist.
4. Confirms LoRA rank `r <= 32`.
5. Creates a clean root-level `submission.zip` containing only:
   - `adapter_config.json`
   - `adapter_model.safetensors`

Notebook C does not train.
